# 開源參考路線圖

這份文件是給目前專案的實作路線，不只看「可以參考誰」，還要明確知道「先做什麼、怎麼接到你現有架構」。

目標：做出「像 LobeChat 一樣完整的使用體驗」，但核心仍是你自己的後端工作流、記憶系統與多智能體協同。

## 先看結論

- 要學 `產品整合 + UI`：看 `LobeChat`
- 要學 `本地模型 / 自架體驗`：看 `Open WebUI`
- 要學 `知識庫 / workspace / 文件餵養`：看 `AnythingLLM`
- 要學 `多模型聊天平台`：看 `LibreChat`
- 要學 `桌面本地模型應用感`：看 `Jan`

## 專案對照與可借用能力

### LobeChat

- 用途：完整 AI chat 產品體驗、多模型、插件與擴充
- 可借用：
  - 產品互動流程
  - UI 完整度與自訂化
  - 多供應商入口
  - 擴充插件心智模型
- 不建議照搬：
  - 前端承擔過重（把路由/記憶/決策塞進 UI）
  - 權限邊界不清的插件執行

來源：

- <https://github.com/lobehub/lobe-chat>

### Open WebUI

- 用途：本地模型、自架、Ollama 整合
- 可借用：
  - 自架與部署流程
  - 本地模型生命週期管理
  - 多後端接法（本地與雲端切換）

來源：

- <https://github.com/open-webui/open-webui>

### AnythingLLM

- 用途：知識庫、工作區、文件導入、RAG
- 可借用：
  - 文件餵養（ingestion）流程
  - workspace 與資料隔離
  - 向量檢索與知識管理
  - 文件到可檢索知識的轉換規則

來源：

- <https://github.com/Mintplex-Labs/anything-llm>

### LibreChat

- 用途：多供應商 AI chat 平台
- 可借用：
  - Provider 抽象層
  - 多模型路由與回退策略
  - 對話平台化能力

來源：

- <https://github.com/danny-avila/LibreChat>

### Jan

- 用途：桌面本地 LLM 應用
- 可借用：
  - 桌面產品感
  - 本機模型互動體驗
  - 本地推理 UX

來源：

- <https://github.com/menloresearch/jan>

## 你目前架構的對接重點

### 1. 知識與記憶（AnythingLLM 路線）

- 對應現況：
  - `opai本地`
  - `data/knowledge_hub`
  - `SQLite + FAISS`
  - `LocalMemoryAPI`
- 落地重點：
  - 統一文件入口（避免重複 md）
  - ingestion 後自動重建三層記憶
  - 回答時自動插入 top-k 長期記憶片段

### 2. 模型路由（LibreChat + Open WebUI 路線）

- 對應現況：
  - NVIDIA/OpenAI-compatible
  - Ollama/Open-Source
  - offline fallback
- 落地重點：
  - 正式 `Model Router`（不要放在桌面層零散判斷）
  - 新增硬體感知切換與節能自動路由
  - 本地不夠時自動切雲端或分批執行

### 3. 工具與任務執行（LangGraph 主流程）

- 主流程固定：
  - `Planner -> Router -> Executor -> Verifier -> MemoryWriter`
- 必備制度：
  - 工具註冊表（輸入、輸出、失敗格式）
  - 任務狀態機（目前步驟、成功/失敗、是否重試）
  - 驗證機制（執行完成後驗真，不直接視為成功）

### 4. 任務可觀測性

- 已有：
  - 任務面板
  - workflow logs
  - step status
  - verification notes
- 需要補齊：
  - 每步耗時
    - `TaskStepState.duration_ms`
    - `attempt_logs[].duration_ms`
  - 每步輸入輸出展開
    - 預設摘要
    - 可展開完整 `input/output + attempt_logs`
  - 錯誤分類
    - `security_path` / `network_error` / `http_error` / `config_or_input_error` / `verification_failed` / `runtime_error`
  - 指定步驟重跑
    - 重跑該步與後續
    - 保留原任務，另建 rerun 任務 ID

## 優先順序（建議直接照這個做）

1. 穩定底座：固定 `.venv` Python 3.12、統一 `.env` 載入與檢查、清理重複文件入口。
2. 路由核心：完成 `Model Router` 與硬體感知節能策略（本地/雲端/分批）。
3. 執行核心：LangGraph 單一主流程 + 工具註冊表 + 任務狀態機 + 驗證機制。
4. 記憶核心：三層記憶自動寫入與 top-k 長期記憶回灌回答。
5. 介面層：桌面 UI 維持「輸入/觀測/控制面板」，不承擔流程決策。

## 產品方向建議（避免打圈）

不要做成「只像 LobeChat 的外觀 + 角色 prompt」。  
建議定位為：

- 前端體驗參考 `LobeChat`
- 知識流參考 `AnythingLLM`
- 本地與自架體驗參考 `Open WebUI`
- 多模型抽象參考 `LibreChat`
- 桌面感參考 `Jan`

保留你自己的核心特色：

- 總管工作流
- 三層長期記憶
- 多智能體協同（有執行能力，不是只分角色）
- 工作區導向
- 後端主導，桌面僅做輸入、可視化與人工決策確認
