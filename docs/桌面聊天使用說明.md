# 桌面聊天使用說明

本說明對應專案主入口 [desktop_chat_app.py](/Volumes/智能體/城城城程式/desktop_chat_app.py) 與 `templates/` 內桌面介面。
目前桌面端的定位是：

- `桌面 UI`：輸入、查看狀態、查看智能體與工作流進度
- `後端工作流`：`LangGraph + workflow runtime`
- `記憶系統`：`LocalMemoryAPI + SQLite + FAISS`
- `模型後端`：`NVIDIA/OpenAI-compatible` 主處理；`Ollama/Open-Source` 僅限語言討論；最後才是離線回退
- `路由策略`：集中在 [core/backend_router.py](/Volumes/智能體/城城城程式/core/backend_router.py)，桌面層只呼叫策略，不自行判斷流程

這份文件已依照 2026-03-24 現況更新，重點是反映現在真的能做什麼，而不是早期設計稿。

---

## 一、先準備什麼

1. 建議使用專案內 `.venv` 啟動桌面程式，不要混用不同 Python 環境。
2. `Python 3` 與核心套件：至少需要 `pywebview`。

   ```bash
   pip install pywebview
   ```

3. 若要用開源對話，請先啟動 `Ollama` 並確認模型已下載。
4. 若要用主要雲端後端，請確認 [500/llama32-chat/.env](/Volumes/智能體/城城城程式/500/llama32-chat/.env) 已有 `NVAPI_API_KEY`、`OPENAI_BASE_URL`、`OPENAI_MODEL`。
5. 工作目錄應為專案根目錄，或使用 `--workspace` 指向專案根。

若要建立可重現的 Python 3.12 CI 基準環境：

```bash
bash tools/setup_py312_agent_env.sh ci
```

若要安裝完整桌面執行依賴，改用 `bash tools/setup_py312_agent_env.sh runtime`。

注意：專案根目錄目前沒有 `.env`；桌面主程式讀取的是 `500/llama32-chat/.env`。

### Python 版本提醒

- 目前系統 `python3` 是 `Python 3.14.2`
- 這個版本很新，語言本身功能較新，但部分 AI 套件相容性還不夠穩
- 專案目前可運作，但 `LangGraph/LangChain` 仍會出現 `Python 3.14` 相容性警告
- 如果之後要追求更穩定的 AI 生態，通常 `Python 3.12` 會比 `3.14` 更穩

簡單講：

- `3.14`：新、能用、部分套件還在追相容
- `3.12`：較成熟、第三方 AI 套件支援通常更完整


## 三、桌面端目前能看到什麼

不加旗標時，預設會開多視窗。核心概念是：

1. 聊天視窗
   - 主要輸入介面
   - 現在會優先走 `總管 -> LangGraph -> workflow runtime`
   - 已支援 `top-k` 長期記憶自動插入

2. 監控區
   - 系統健康分數
   - VS Code / Ollama / 模型 / 智能體狀態
   - 即時監控數字

3. 任務面板
   - 顯示最近一次工作流
   - 路由角色
   - 驗證是否通過
   - 每一步工具是否成功
   - 每步耗時（`duration_ms`）
   - 每步錯誤分類（`error_class`）
   - 每步完整輸入/輸出展開（含 `attempt_logs`）
   - 可重跑指定步驟（重跑該步 + 後續）
   - 重試次數
   - 任務日誌路徑

4. 語義標籤分析
   - 每次訊息會做詞語解構（關鍵詞、連接詞）
   - 會標記領域（例：腦科學、心理學、程式工程）
   - 會給出協作角色建議（總管/研究員/工程師/中繼器/小編/申言者）
   - 會顯示部首訊號（同部首重複特徵）
   - 分析紀錄會寫入 `data/knowledge_hub/interaction_tags.jsonl`

5. 各智能體視窗
   - 研究員、工程師、中繼器、小編、申言者
   - 帽子需對應模組已載入

6. 自定義版面
   - 右側有「自定義版面」區塊，可直接編輯 JSON
   - 可調整欄位比例、面板透明度、字體縮放
   - 設定會儲存在瀏覽器 localStorage

所有視窗共用同一個 `DesktopBridge`，所以資料與狀態是一致的。

### 可選：少開幾個視窗

- `--no-monitor-window`：不要監控視窗。
- `--no-agent-windows`：不要各智能體視窗（只留聊天）。
- `--energy-lite`：節能模式，預設「聊天 + 監控」，不開各智能體獨立視窗，並降低輪詢頻率。

```bash
python3 desktop_chat_app.py --no-monitor-window
python3 desktop_chat_app.py --no-agent-windows
python3 desktop_chat_app.py --energy-lite
```

## 四、單一視窗模式

以下四者**擇一**，不可同時使用：

| 參數                | 效果                                                 |
| ------------------- | ---------------------------------------------------- |
| `--unified`         | **單一傳統介面**：`chat.html`（聊天 + 右側監控同頁） |
| `--only-chat`       | 只開 **聊天（總管主線）**，含外掛列                  |
| `--only-monitor`    | 只開 **監控面板**                                    |
| `--only-agent 角色` | 只開 **一個智能體** 視窗                             |

### `--only-agent` 可用角色

必須完全符合下列字串之一：

- `總管` — 精簡對話頁（**與** `--only-chat` **不同**：後者有外掛列與主聊天版面）
- `研究員`
- `工程師`
- `中繼器`
- `小編` — 文案、改寫、標題與摘要等（與聊天裡「請小編／@小編」同一路由）
- `申言者` — 道德分析、價值衝突拆解、信仰/聖經脈絡整理（可搭配「以利亞」角色模型）
- `帽子` — 需帽子模組已載入，否則程式會報錯並結束

申言者專用 profile/prompt 檔：`config/agent_profiles/prophet_profile.json`（由 `prompt_file` 載入 `config/agent_profiles/prophet_prompt.md`）。
全智能體共用提示詞：系統會優先讀取 `500/llama32-chat/openai_format_analysis.json` 內的 ChatGPT 自訂指示快照；若找不到，才 fallback 到 `config/agent_profiles/global_chatgpt_prompt.md`。
一鍵同步入口：`tools/sync_chatgpt_custom_instructions.sh`

同步最新版 custom instructions：

```bash
./tools/sync_chatgpt_custom_instructions.sh
```

若你的最新匯出在其他位置，可指定來源檔：

```bash
./tools/sync_chatgpt_custom_instructions.sh --source /你的/匯出檔.json
```

範例：

```bash
python3 desktop_chat_app.py --only-chat
python3 desktop_chat_app.py --only-monitor
python3 desktop_chat_app.py --only-agent 研究員
python3 desktop_chat_app.py --only-agent 總管
python3 desktop_chat_app.py --only-agent 小編
python3 desktop_chat_app.py --only-agent 申言者
```

## 六、前端檔案對照

| 檔案                           | 用途                                 |
| ------------------------------ | ------------------------------------ |
| `templates/chat_shell.html`    | **主要前端主線**（建議主入口）       |
| `templates/chat.html`          | 傳統整合版（聊天 + 監控 + 任務面板） |
| `templates/monitor_shell.html` | 僅監控                               |
| `templates/agent_shell.html`   | 單一智能體頁                         |
| `templates/desktop_glass.css`  | 分頁介面共用樣式                     |

### Web 路由策略（chat_shell-first）

- 主入口：`/` 會轉址到 `/chat_shell`
- 主聊天頁：`/chat_shell`
- 相容保留：`/chat`（整合版仍可用）
- 相容別名：`/chat-shell`、`/monitor-shell`、`/agent-shell` 會轉到底線路由

### 為什麼 chat_shell 體感較好

- 職責單一：只做聊天主線，頁面負擔比整合版小。
- 監控解耦：監控頁獨立，不會跟聊天 DOM/輪詢互相干擾。
- 玻璃化樣式集中：`desktop_glass.css` 的互動狀態（含運作提示）更穩定。

### 最小 E2E 檢查

```bash
.venv/bin/python tools/check_chat_shell_e2e.py
```

會檢查：

- `/` 是否正確轉址到 `/chat_shell`
- `/chat_shell` 是否可載入
- `/chat` 是否仍可用（相容）
- `/api/get_status` 是否可回應

## 七、目前工作流怎麼跑

現在的主線不是只有角色分配，而是：

1. `Planner`
2. `Router`
3. `Executor`
4. `Verifier`
5. `MemoryWriter`

其中 `Executor` 會透過工具註冊表執行真實工具，像是：

- 讀取模型設定
- 查知識中樞
- 查長期記憶
- 搜尋工作區
- 讀取檔案
- 寫知識筆記
- 產生工作流報告

工作流執行後，會留下：

- 任務執行日誌：`data/workflow_runs/`
- 知識筆記：`data/knowledge_hub/notes/`
- 工作流報告：`reports/workflow_runs/`

### 任務可觀測性補強（2026-03-29）

- 每一步都記錄 `started_at / finished_at / duration_ms`。
- 每一步新增 `error_class`，常見類別：
  - `security_path`
  - `network_error`
  - `http_error`
  - `config_or_input_error`
  - `verification_failed`
  - `runtime_error`
- 每一步保留 `attempt_logs`，可展開看每次嘗試的耗時與錯誤。
- 支援「指定步驟重跑」：
  - 預設為「重跑該步 + 後續步驟」。
  - 會產生新的 rerun 任務 ID 與日誌（保留原任務）。

### API 申請流程（CLI + 桌面互動）

- CLI（流程與檢查）：
  - `python3 tools/api_onboarding.py`
  - `python3 tools/api_onboarding.py --provider nvidia`
  - `python3 tools/merge_env_files.py --workspace /Volumes/智能體/城城城程式`
  - `python3 tools/merge_env_files.py --workspace /Volumes/智能體/城城城程式 --apply`
- 桌面互動卡：
  - 顯示主 `.env`、模型狀態、供應商 key 狀態。
  - 提供供應商申請頁入口（NVIDIA / Gemini / Groq / OpenAI / xAI）。
  - 支援複製 Key 名稱，減少填錯。

### 模型路由補充（2026-03-24）

- 判定為 `execution`（例如「修復/建立/導入/索引」）時：優先 NVIDIA；不走開源聊天回退。
- 判定為 `discussion`（一般討論）時：NVIDIA 優先，失敗才可回退到 Ollama。
- 路由判定來源：關鍵字 + `task_state`（如 `completed_steps`、`overall_status`）。

### 節能自動路由（2026-03-29）

- 新增硬體感知（CPU/記憶體）並回寫到監控面板。
- 負載偏高時會進入 `energy_saving`，限制本地模型回退以降低本機耗電。
- 負載過高時會進入 `critical_offload`，提示「分批打包」執行。
- 預設採雲端優先（你定義的「不需要電腦跑的盡量外包」）。

## 八、目前已知限制與注意事項

1. `LangGraph` 在 `.venv` 環境可用，但 `Python 3.14` 仍有相容性警告。
2. 系統 `python3` 和 `.venv/bin/python` 的能力不同，若直接裸跑 `python3`，某些套件可能不存在。
3. 桌面 UI 應只負責輸入與觀察；實際流程、記憶、工具執行應留在後端。
4. `Ollama` 若沒啟動，桌面端會回退到雲端或離線模式。
5. 目前總管雖已大幅收斂到工作流，但少數系統級快捷指令仍保留直接處理。
6. 語義分析屬啟發式規則，不等於完整語言學解析；如需更高精度，建議再接分詞模型。
7. `.env` 可能分散在不同路徑，已新增融合工具，建議定期執行：

```bash
./.venv/bin/python tools/merge_env_files.py --workspace /Volumes/智能體/城城城程式
./.venv/bin/python tools/merge_env_files.py --workspace /Volumes/智能體/城城城程式 --apply
```
