# 智能體能力強化路線圖

## 目標
將「情境感知、多模態、即時處理、安全、自我學習、協作、跨域應用」七大方向，轉為可迭代的工程落地項目。

## 優先順序（建議）
1. 強化安全性（先保護系統與資料）
2. 即時數據處理（先提升回應速度與穩定性）
3. 強化情境感知（先提升決策品質）
4. 自我學習與優化（讓系統持續進化）
5. 增強協作能力（擴大多智能體產能）
6. 多模態交互（提升使用體驗）
7. 擴展應用領域（垂直場景落地）

## 能力模組設計

### 1) 強化情境感知
- 核心能力：
  - 使用者意圖分類（問答、執行、排程、風險處理）
  - 環境狀態感知（CPU、記憶體、服務存活、資料新鮮度）
  - 任務上下文記憶（短期對話 + 中期任務狀態）
- 實作建議：
  - 新增 `context_state` 聚合器，統一輸入「系統狀態 + 對話意圖 + 任務歷史」。
  - 在任務路由前插入 context policy 判斷。
- 驗收指標：
  - 任務誤派率下降
  - 需追問次數下降

### 2) 多模態交互
- 核心能力：
  - 文字、語音、圖像統一輸入與標準化
  - 多模態訊號融合（例如 OCR + 文字推理）
- 實作建議：
  - 建立 `multimodal_ingest` 入口與標準 payload（`type`, `content`, `meta`）。
  - 先做「圖像 + 文字」雙模態 MVP，再擴語音。
- 驗收指標：
  - 圖文任務完成率
  - 多模態請求平均處理延遲

### 3) 即時數據處理
- 核心能力：
  - 事件流式處理
  - 快速告警與快速回復
- 實作建議：
  - 將監控資料改為事件驅動（queue/buffer + worker）。
  - 補齊延遲監控與 timeout 重試策略。
- 驗收指標：
  - P95 回應時間
  - 告警到處置時間（MTTR）

### 4) 強化安全性
- 核心能力：
  - 最小權限、金鑰保護、請求簽章、審計追蹤
  - 風險操作雙重確認（高風險工具、寫入操作）
- 實作建議：
  - 補齊 API token 驗證中介層與來源白名單。
  - 增加安全審計事件（登入、權限變更、敏感存取）。
- 驗收指標：
  - 未授權請求攔截率
  - 安全事件可追溯率

### 5) 自我學習與優化
- 核心能力：
  - 從任務結果回饋學習（成功/失敗原因）
  - 自動調參（路由策略、模型選擇、重試策略）
- 實作建議：
  - 建立 `feedback_loop`：收集 outcome -> 產生策略調整建議 -> 灰度套用。
  - 對失敗任務做 root-cause 標註。
- 驗收指標：
  - 任務成功率週趨勢
  - 重複錯誤率下降

### 6) 增強協作能力
- 核心能力：
  - 多智能體角色分工（Planner/Router/Executor/Reviewer）
  - 負載平衡與衝突解決
- 實作建議：
  - 統一任務契約（輸入、輸出、責任邊界）。
  - 增加協作看板：任務佇列、阻塞原因、資源占用。
- 驗收指標：
  - 任務吞吐量
  - 平均等待時間

### 7) 擴展應用領域
- 核心能力：
  - 垂直場景流程模板（醫療、製造、教育等）
  - 場景特定規範與合規檢查
- 實作建議：
  - 先做 1 個高價值場景 PoC（建議教育或知識工作流）。
  - 場景化配置（policy、詞庫、工具白名單）。
- 驗收指標：
  - 場景任務完成率
  - 使用者滿意度

## 90 天執行節奏（建議）
- 第 1-30 天：
  - 安全強化 + 即時處理基礎建設
  - 建立觀測指標（延遲、失敗率、攔截率）
- 第 31-60 天：
  - 情境感知 + 自我學習回饋迴路
  - 協作契約與角色路由優化
- 第 61-90 天：
  - 多模態 MVP
  - 1 個垂直場景 PoC 落地

## 推薦先做的三件事
1. 建立統一的 `context_state` 與安全審計事件模型
2. 導入即時事件隊列與 P95 延遲監控
3. 建立任務結果回饋資料結構（供自我學習）
