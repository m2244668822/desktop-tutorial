# Perob 前端完整微文案優化設計

- 日期：2026-08-21
- 狀態：設計方向已確認，待書面規格複核
- 方案：完整微文案整理

## 背景

Perob 目前由 `5001` 提供後端與前端，根路徑會導向
`/chat_shell`，`5443` 則提供 HTTPS 代理。服務已可正常運作，
但前端仍有權限名稱矛盾、泛用載入文字、內部術語與操作提示不清等問題。

最明顯的例子是「最低權限」按鈕。它實際會附帶 bypass 標記並允許
外部代理流程，名稱卻容易讓使用者誤以為風險較低。此外，四份 shell
模板各自保存相同文案，容易產生不一致。

## 目標

1. 讓權限、連線、載入、空狀態與錯誤文案準確反映真實行為。
2. 讓操作按鈕清楚說明動作、影響與下一步。
3. 移除未解釋的內部術語，改用使用者可理解的角色描述。
4. 讓四份 Perob shell 模板使用一致詞彙。
5. 補足圖示按鈕的無障礙名稱與提示。

## 非目標

- 不改動 CSS 版面、色彩、元件排列或響應式結構。
- 不改動 API、路由、資料格式、智能體分流或權限判斷。
- 不改動雙重確認送出的安全機制與八秒確認窗口。
- 不重構四份重複模板；模板共用化屬於另一個架構方案。
- 不處理 `agent-network-monitor` 或其他非 Perob shell 頁面。

## 修改範圍

以下四份模板必須同步更新：

- `templates/chat_shell.html`
- `templates/chat.html`
- `templates/agent_shell.html`
- `templates/monitor_shell.html`

可修改的內容限於：

- 使用者可見文字
- JavaScript 產生的使用者可見狀態與錯誤訊息
- `title`、`aria-label` 等提示與無障礙屬性

現有元素 `id`、函式名稱、事件處理器與 API 呼叫必須保持不變。

## 標準詞彙

### 品牌與頁面標題

- 瀏覽器標題由「AI 智能體中心」改為「Perob 智能體中心」。
- 保留既有 XIUORAN 圖像標誌，不調整品牌圖形或版面。

### 外部代理權限

- 關閉狀態：`外部代理直通：關閉`
- 開啟狀態：`外部代理直通：開啟`
- 提示文字：`啟用後會附帶 bypass 標記並允許外部代理流程；`
  `僅在明確需要時開啟。`

所有使用者可見的「最低權限」文字都必須移除。程式註解也改用
「外部代理直通」，避免維護者再次誤解。

### 連線狀態

連線狀態統一使用以下詞彙：

- 等待：`正在連線…`
- 成功：`後端已連線`
- 警告：`後端連線異常`
- 失敗：`無法連線後端`
- 手動動作：`重新檢查連線`

n8n 未啟動時必須顯示為
`n8n 未啟動（不影響核心對話）`，不得與必要服務失敗混為一談。

### 載入與空狀態

避免只顯示「載入中」。每個區域都要說明正在載入什麼：

- 對話紀錄：`正在載入對話紀錄…`
- 學習狀態：`正在載入學習狀態…`
- 任務清單：`正在載入任務…`
- 歸檔清單：`正在載入歸檔…`

空狀態統一使用「目前沒有」：

- `目前沒有對話紀錄`
- `目前沒有符合條件的任務`
- `目前沒有歸檔`
- `目前沒有學習紀錄`

### 操作按鈕

操作名稱改成完整、可預測的動作：

- `↻ 重整` 改為 `↻ 重新整理狀態`
- `↻ 重載任務` 改為 `↻ 重新載入任務`
- `🔄 重新聯網` 改為 `🔄 重新檢查連線`
- `💾 打包存硬碟` 改為 `💾 匯出歸檔`
- `🗑️ 清理 30 天前` 改為 `🗑️ 清理 30 天前歸檔`
- `⚠️ 清理 7 天前` 改為 `⚠️ 清理 7 天前歸檔`

清理按鈕的提示必須明確說明會移除指定日期以前的歸檔。

### 訊息送出

保留現有雙重確認流程，並讓提示準確描述行為：

- 輸入提示：
  `輸入訊息；連按兩次 Enter 或送出按鈕，Shift+Enter 換行…`
- 圖像模式提示：
  `描述要生成的圖片；連按兩次 Enter 或送出按鈕…`
- 預設按鈕：`送出訊息`
- 第一次確認後：`再按一次確認送出`
- 處理中：`後台處理中`
- 預設提示：`為避免誤送，需要連續確認兩次。`
- 待確認提示：`請在八秒內再按一次以送出。`

### 智能體角色描述

角色描述以「能協助什麼」為主，不顯示遷移歷史或未解釋縮寫：

- 申言者中樞：說明需求分流、風險分級、任務拆解與多智能體協調。
- 研究學習中樞：說明研究、知識整理、分類索引與學習循環管理。
- 工程師：說明程式修復、Git 追查、技術協作與額外權限說明。
- 小編設計師：說明文案、視覺、圖片生成、標題與摘要能力。
- 申言者：說明倫理、價值衝突、跨文化與聖經脈絡分析。
- 白帽駭客：說明安全評估、漏洞分析、測試報告與防禦建議。
- 通用助手：說明一般問答、腦力激盪、規劃與文字整理。

相容入口可以說明會轉交哪個智能體，但不使用「舊入口已併入」等
內部遷移文案。`KAL` 若必須保留，第一次出現時寫成
「知識學習循環（KAL）」。`SMP` 不顯示給一般使用者。

## 錯誤訊息設計

錯誤訊息固定採用「發生情況、影響、下一步」順序：

1. 先以自然語言說明目前情況。
2. 說明是否影響核心對話或只影響可選功能。
3. 提供同步、重試、切換模型或檢查連線等下一步。
4. 必要時在句尾保留 HTTP 狀態或原始錯誤摘要。

前端等待逾時不應描述為智能體故障。標準訊息為：

`任務可能仍在處理，或前端等待時間已到。請先同步或重試；`
`若持續發生，再依 5001 → 5443 → 前端順序檢查。`

模型逾時、路由不匹配、連線失敗與伺服器錯誤仍維持不同分類，
不得全部合併成泛用的「發生錯誤」。

## 無障礙與提示

- 圖像生成、附加圖片、關閉燈箱與移除附件按鈕補上 `aria-label`。
- 只有圖示的控制項必須有清楚的 `title`。
- 危險操作的提示必須包含影響範圍。
- 不以 emoji 單獨承擔動作語意。

## 資料流與行為邊界

後端回應、HTTP 狀態與 API 錯誤碼維持原樣。前端既有函式仍負責：

1. 取得後端狀態或執行結果。
2. 將技術狀態分類為等待、成功、警告或失敗。
3. 顯示本規格定義的文案。

本次不新增文案 API 或共用 JavaScript 字典。四份模板的同步一致性由
契約測試保護，避免在內容優化中混入模板架構重構。

## 測試策略

先新增失敗的內容契約測試，再修改模板。測試必須：

- 逐一讀取四份模板。
- 確認標準標題、權限狀態與主要操作文字都存在。
- 確認「最低權限」與其他已淘汰的使用者文案不再存在。
- 確認四份模板使用相同的送出、載入、空狀態與連線詞彙。
- 確認圖示按鈕具有必要的 `aria-label`。

完成後執行：

- 新增的內容契約測試
- 既有前端與主線健康契約測試
- `bash tools/run_full_verification.sh`
- `git diff --check`
- 重新啟動 `tools/manage_perob_stack.sh restart`
- 檢查 `5001`、`5443`、`/health/live`、`/health/ready` 與
  `/chat_shell` 的實際回應

## 風險與控制

- 較長按鈕文字可能影響窄螢幕；修改前先確認按鈕沒有固定寬度，
  並在驗證時檢查產出的 HTML 與相關 CSS 約束。
- 四份模板可能再次漂移；內容契約測試必須同時檢查四份檔案。
- 錯誤訊息過度簡化可能隱藏診斷資訊；保留必要狀態碼與技術摘要。
- 外部代理直通具有風險；名稱、狀態與提示必須同時明示。

## 驗收標準

1. 四份模板通過相同的內容契約測試。
2. 使用者介面不再顯示「最低權限」。
3. 外部代理直通的開關狀態與風險說明清楚可見。
4. 載入、空狀態、連線與錯誤文案皆能指出具體情況與下一步。
5. 智能體描述不含未解釋的內部遷移術語或縮寫。
6. 圖示按鈕具有可辨識的無障礙名稱。
7. 既有 API、路由、雙重確認送出與智能體行為沒有改變。
8. 完整驗證通過，重啟後 `5001` 與 `5443` 保持健康。
