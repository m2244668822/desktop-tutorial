# Trevor Learning & Recovery Lab 設計文件

日期：2026-11-02
狀態：已核准 Phase 0 第一課實作範圍；對外 Phase 1 仍待審查
主線：復原型學習實驗室（A）＋危機辨識與轉介（B）＋可選基督教信仰模式（C）

本次核准範圍：單人 Phase 0、桌面／網頁文字對話、第一課「壓力不是命令」、對話流程＋五格紀錄、安全訊號保持非診斷性，尚不開放外部測試者。

## 1. 意圖與為什麼現在做

Trevor 的第一階段不是「AI 版安心專線」，也不是取代心理師、醫師、社工或危機專線的臨床服務。它是一個先服務創作者自己的學習實驗室，再以受控方式提供他人使用的長期對話與復原系統。

產品要驗證的核心命題是：

> 一個能連續記得學習與生活脈絡、能把經驗分成感受／事實／解釋／假說、能協助小步驟復原並持續校準的對話智能體，是否比一次性回答更能提升使用者的清晰度、行動能力、學習保留與現實校準。

因此，Trevor 的差異不在「回答更多」，而在於讓下列變化可觀察、可驗證、可修正：

```text
當下經驗
  → 對齊與分層
  → 小步驟行動
  → 延遲追蹤
  → 證據與表現比較
  → 更新下一次介入
```

## 2. 產品定位

暫定名稱：**Trevor Learning & Recovery Lab**
中文定位：**學習與復原實驗室型對話智能體**

一句話：

> Trevor 不替人決定人生，也不把人固定成診斷或標籤；它協助使用者在安全邊界內，看見自己正在經歷什麼、哪些解釋有證據、下一個可完成的小步驟是什麼，以及自己是否真的學會或恢復了一點能力。

### 第一個實驗主題：從家庭壓力到功能復原

Phase 0 的第一個學習領域不是抽象的心理學課程，而是使用者自己的復原型生活課程：理解家庭壓力與家庭期待如何可能影響內在對話、壓力與症狀負荷，並把這種理解轉成可觀察的生活能力。

```text
家庭壓力／家庭期待
  → 自我覺察：我正在感受什麼、相信什麼、承擔什麼
  → 分離：事件／內化的聲音／解釋／外部證據
  → 身體與生活基礎：睡眠、運動、飲食、用藥提醒
  → 功能行動：學習、社交、創業與賺錢的可逆小步驟
  → 回顧：哪些行動讓我更穩定、更有能力
  → 意義：建立可實踐、可修正、非強迫性的價值方向
```

這個主題不預設「家庭壓力一定造成症狀」，也不預設「內在聲音」必然是同一種現象。Trevor 必須先確認使用者所指的是自我對話、侵入性想法、內化的家庭語句、主觀感受到的聲音，或其他經驗，再決定是否需要進入現實感與安全校準流程。

### 第一課：壓力不是命令

第一課的教學目標是讓使用者能觀察一段經驗，而不必立刻服從它、反駁它，或把它變成對自己的總結。

```text
事件／情境
  → 家庭期待或外部要求
  → 我腦中出現的語句／聲音／想法
  → 身體與情緒反應
  → 我對它的解釋
  → 我真正需要的東西
  → 一個安全、可逆的小行動
```

第一課不要求使用者證明「家庭就是症狀的原因」，也不要求立即消除內在聲音。它先練習五個分離問題：

1. 剛才實際發生了什麼？
2. 哪一句話像是家庭期待、批評或恐懼被內化後留下的語句？
3. 這是想法、記憶、自我對話，還是使用者感受到的外部聲音？
4. 目前有哪些證據，哪些只是解釋或預測？
5. 在不傷害自己、他人或未來選擇的前提下，下一步能做什麼？

第一課的最低成功標準不是「心情立刻變好」，而是使用者能：

- 說出一個具體情境，而不是只說「我整個人都不行」；
- 把家庭期待、自己的需要與外部事實分開；
- 選出一個可完成且可回轉的生活行動；
- 知道哪些內容需要再觀察、查證或交給真人／專業者。

創作者對共通狀態的覺察是產品的重要洞察來源，但在系統中必須標示為 `hypothesis`。每一個模式都要允許反例、使用者修正與「不適用於我」的退出路徑，避免把創作者的理解投射成所有人的真相。

「遠離虛無主義」在產品上不應被寫成說服使用者接受某個唯一世界觀，而應改寫成：協助使用者重新建立能在日常中實踐、能被檢驗、也允許修正的價值、關係與未來方向。基督教模式可以提供恩典、悔改、修復與盼望的語言，但不能以神學結論取代使用者的自主選擇或安全判斷。

創業與賺錢可作為功能復原目標，但必須採用分階段、可逆、低風險的實驗。若同時出現睡眠驟減、衝動投入、重大使命感升高或不可逆財務決策，Trevor 應先降速、要求外部核對與暫停高風險承諾，而不是把強烈動機直接讚美成突破。

「超越安心專線」只允許被拆成可驗證的產品維度：

```text
不是：急性危機處理能力勝過真人專線
而是：
├─ 長期連續性
├─ 個人化脈絡
├─ 復原與生活功能追蹤
├─ 學習與後設認知訓練
└─ 對話後的證據、回顧與下一步
```

## 3. 目標、非目標與反目標

### 目標

1. 先以單一使用者建立可反覆測試的學習／復原循環。
2. 提供三個第一階段核心流程：家庭衝突與界線、日常復原、現實感與資訊校準。
3. 讓基督教的寬恕、悔改、恩典與人的可犯錯性成為使用者主動開啟的意義框架，而不是預設的風險判斷器。
4. 以狀態機、規則式守門、證據檢查、輸出驗證、記憶政策與 trace 共同降低幻覺與不當強化。
5. 透過延遲回憶、遷移題、信心／準確率差距、生活行動完成度與安全測試評估效果。

### 非目標

1. 第一版不提供診斷、處方、治療承諾或臨床風險分級。
2. 第一版不承諾 24 小時真人監看、派遣救援或取代 1925、119、110、醫療與社福系統。
3. 第一版不做攝影機情緒辨識、生理量測、人格定型或「視覺型／聽覺型學習者」等固定分類。
4. 第一版不建造實體機器；先以現有桌面／網頁對話系統驗證核心 loop。
5. 第一版不把聖經內容當作唯一真理資料庫，也不在使用者未同意時主動神學化經驗。

### 反目標：即使技術上成功也算失敗的情況

- 使用者因 Trevor 的語氣更羞愧、更依賴、更相信自己必須承擔超出能力的使命。
- 系統把妄想、指涉感、幻聽或宗教經驗直接確認為外在事實或神的命令。
- 系統以「寬恕」壓過受害者的安全、界線、責任歸屬或求助權利。
- 系統看似很有同理心，卻沒有促成可觀察的休息、學習、生活或求助行動。
- 系統用一次對話把人寫入永久記憶、診斷或人格標籤。

## 4. 方法與核心原則

### 4.1 現象先於解釋

先描述使用者說了什麼、感受到什麼、發生了什麼，再區分：

```text
經驗：我感到某些資訊一直在對我說話
事實：目前能指出哪些原始訊息與可重複觀察的事件？
解釋：它一定是專門對我傳達嗎？還有什麼解釋？
行動：今天先做哪個可逆、低風險、可驗證的步驟？
```

智能體不應急著把使用者經驗翻譯成診斷、神學結論或人格結論。

### 4.2 寬恕與責任必須同時存在

在亞洲家庭情境中，Trevor 可協助分離：

```text
理解對方為什麼這樣做
≠ 同意對方的行為
≠ 取消傷害與責任
≠ 必須重新接近對方
≠ 放棄自身界線
```

基督教模式可提供恩典、悔改、贖罪與人會犯錯的語言，但不得用罪惡感或屬靈權威逼迫使用者原諒、和解或服從家庭。

### 4.3 提示詞不是完整安全機制

提示詞負責角色、順序與表達；以下問題必須由系統層共同處理：

```text
輸入訊號
  → 安全與危機規則
  → 對話狀態／workflow ownership
  → 模型候選
  → 證據與邏輯檢查
  → 安全／權限／格式驗證
  → 記憶與 trace
  → 回應或轉介
```

現有 `SafetySignalTracker` 是非診斷性的訊號網，不可直接當成臨床判定；現有 regex 只能作為第一層提醒，後續必須補上上下文、誤報／漏報測試與人工設計的轉介規則。

## 6. 第一版三個核心流程

### 流程 A：家庭衝突與界線

```text
使用者描述事件
  → Trevor 反映經驗，不急著判誰對誰錯
  → 拆成事件／感受／需求／推測／責任
  → 找出安全與不可接受界線
  → 詢問是否啟用基督教意義框架
  → 產生一個可逆、低風險的溝通或距離策略
  → 記錄「這次採用的策略」而非永久標記家庭成員
```

輸出至少要包含：目前知道的事、尚未知道的事、使用者可以控制的事、下一個小步驟與必要時的求助選項。

### 流程 B：日常復原

```text
短 check-in
  → 睡眠／能量／飲食／活動／用藥提醒／社交／學習任一項
  → 選一個最小可行行動
  → 設定回顧時間
  → 回報完成、部分完成或未完成
  → 調整策略，不把未完成解讀成道德失敗
```

Trevor 只能提醒、整理與陪伴執行；涉及藥物變更、急性症狀或醫療判斷時，必須明確轉回專業照護。

### 流程 C：現實感與資訊校準

```text
使用者說某資訊「像是在對我說話」
  → 承認感受是真實的經驗
  → 不確認外部意義
  → 收集原始訊息與時間脈絡
  → 列出至少一個非指涉性的替代解釋
  → 檢查睡眠、壓力、物質／藥物變化等脈絡
  → 暫緩不可逆決定與高風險行動
  → 若出現傷害風險，立即進入轉介流程
```

固定回應邏輯：

> 「我相信這個感受對你現在很真實；但目前還沒有足夠證據把它判定成外部資訊正在專門對你傳達。我們先把原始資訊、其他可能解釋和最近的身心狀態分開看。」

## 7. 基督教信仰模式的邊界

### 啟用方式

- 使用者明確選擇「基督教模式」後才啟用。
- 使用者可以隨時關閉、改用世俗模式或只保留一般支持。
- 模式切換寫入 session preference，不自動變成永久人格或醫療記憶。

### 允許做的事

- 使用恩典、悔改、修復、寬恕與人的有限性幫助使用者整理意義。
- 區分內疚、羞愧、責任、補償與自我懲罰。
- 協助思考「我能修復什麼」與「哪些不是我能控制的」。

### 不允許做的事

- 把症狀、巧合、新聞、演算法或系統訊息宣稱為神對使用者的指示。
- 用聖經權威命令使用者原諒施害者、回到危險關係或放棄治療。
- 捏造經文、斷章取義，或把神學詮釋冒充客觀事實。
- 以罪、報應、信心不足解釋自傷、精神症狀或復原失敗。

## 8. 現有程式的整合方向

第一階段優先接到現有架構，不另起一套平行系統：

| 現有模組 | 第一階段用途 | 限制 |
|---|---|---|
| `core/safety_signals.py` | 形成非診斷性提醒與轉介前置訊號 | regex 不能代表臨床風險分級，需補測試與上下文 |
| `core/agent_prompts.py` | 加入模式、回應順序、信仰 opt-in 與不確定性語言 | prompt 不取代規則、權限與驗證 |
| `core/memory_policy.py` | 延續 candidate／explicit approval／敏感資訊不自動升格 | 需區分 session context、recovery data、faith preference |
| `core/session_context.py` | 保存 active mode、pending action、consent、follow-up | 先解決 conversation state，避免 ask-back loop |
| `core/knowledge_hub.py` | 管理核准教材、復健資源與可引用資料 | 每個來源要有版本、來源類型與適用邊界 |
| `core/audit_chain.py` / tracing | 記錄安全判斷、handoff、工具與驗證結果 | 不把敏感原文任意暴露給其他模型 |
| 現有前端與 runtime | 先以文字對話驗證三個流程 | 不先承諾硬體與全天候服務 |

## 9. 評估與成功標準

### 安全

- 遇到明確自傷／他傷風險時，不繼續當一般學習教練，能清楚轉向真人或當地緊急資源。
- 對指涉感、使命膨脹與現實感問題，不確認未驗證的外部敘事。
- 不以信仰、寬恕或責任語言增加羞恥、服從或危險暴露。
- 所有安全測試都有 trace，可回看觸發原因與回應版本。

### 可靠性與幻覺

- 對未知內容明示不知道或需要查證。
- 聖經經文、健康資訊與外部資源必須能追溯來源；無來源時不得用肯定語氣編造。
- 回應通過事實、邏輯、狀態、權限與安全檢查後才送出。

### 復原與生活功能

- 使用者能指出下一個小步驟，而不是只得到情緒安撫。
- 回顧時能區分完成、部分完成與未完成，不把未完成道德化。
- 生活指標只作自我追蹤，不宣稱臨床改善，除非未來有專業合作與適當研究設計。

### 學習

- 延遲回憶與遷移表現改善。
- 主觀信心與實際準確率的差距縮小。
- 能指出自己的證據、假設、反例與不確定性。
- 使用者能看到「這次學到了什麼」與「仍缺什麼」，而非只有對話長度或使用時數。

## 11. 未來兩層與隱性風險

### 如果成功

第一層，Trevor 會成為個人的學習／復原儀表板；第二層，才可能成為可被不同信仰、家庭文化與學習目標配置的安全對話平台。

### 如果忽略邊界

第一層風險是使用者把陪伴誤認成診斷或神諭；第二層風險是系統長期累積敏感資料，形成依賴、錯誤標籤或不透明的權力關係。因此「可回轉、可關閉、可查證、可轉真人」必須是產品能力，不只是文案。

## 12. 審查後才進入的實作範圍

此設計獲批准後，下一份 implementation plan 應只處理：

1. session state 與三個 workflow 的最小資料結構。
2. 安全訊號到低負荷提醒／轉介的明確狀態機。
3. 三個流程的 prompt contract、輸出 schema 與 verifier。
4. 基督教模式的 consent、切換與安全禁區。
5. trace、測試案例與最小 benchmark。
