## ⚡ 快速開始（3 步）

### 步驟 1: 確保 Ollama 運行（1 分鐘）

```bash
# 打開新終端，執行：
ollama serve

# 預期輸出：
# Error: listen tcp 127.0.0.1:11434: bind: address already in use
# 或
# Serving on 127.0.0.1:11434
```

**解釋**:

- ✅ 如果看到 "address already in use" → Ollama 已在運行，正常
- ✅ 如果看到 "Serving on 127.0.0.1:11434" → Ollama 已啟動，正常
- ❌ 如果看到其他錯誤 → 參考故障排除部分

### 步驟 2: 驗證模型（1 分鐘）

```bash
# 在現有終端執行：
ollama list

# 預期輸出：
# phi:latest         1.6 GB  2 hours ago
# llama3.2:latest    2.0 GB  2 months ago
# mistral:latest     4.4 GB  3 weeks ago
```

**要求**: 至少看到 `phi:latest` 在列表中


## ⚠️ 故障排除

### 問題 1: 無法啟動 Ollama

**錯誤信息**:

```
ollama: command not found
```

**解決方案**:

```bash
# 檢查安裝
which ollama

# 如果未找到，安裝 Ollama
# 訪問: https://ollama.ai
# 下載並安裝

# 驗證安裝
ollama --version
```

---

### 問題 2: Phi 模型未找到

**錯誤信息**:

```
⚠️  警告: Phi 模型未找到
```

**解決方案**:

```bash
# 拉取 Phi 模型
ollama pull phi

# 驗證
ollama list | grep phi
# 應該看到: phi:latest    1.6 GB
```

---

### 問題 3: 連接超時

**錯誤信息**:

```
⏱️ 連接超時 (嘗試 1/3): ...
⏱️ 連接超時 (嘗試 2/3): ...
⏱️ 連接超時 (嘗試 3/3): ...
❌ Ollama 連接失敗，切換至本地知識庫模式
```

**原因分析**:

- Ollama 服務未正常運行
- 模型加載時間過長
- 系統資源不足

**解決方案**:

```bash
# 1. 檢查 Ollama 進程
ps aux | grep ollama | grep -v grep

# 2. 檢查 API 端點
curl http://localhost:11434/api/tags

# 3. 重啟 Ollama
pkill ollama
sleep 2
ollama serve &

# 4. 等待 5 秒再重試
sleep 5
python3 offline_local_chat_fixed.py
```

---

### 問題 4: 內存不足

**症狀**:

- 程式變慢或崩潰
- 系統風扇噪音大
- 卡頓或無響應

**解決方案**:

1. 關閉其他應用
2. 切換到更輕量級的模型
3. 重啟系統

```bash
# 如果切換模型，編輯程式
# 找到: self.model = "phi"
# 改為: self.model = "tinyllama"  # 更輕量

# 安裝 TinyLlama (0.6GB)
ollama pull tinyllama
```

---

### 問題 5: 其他錯誤

**通用故障排除流程**:

```
1. 查看詳細日誌
   python3 offline_local_chat_fixed.py 2>&1 | tee debug.log

2. 尋找 [ERROR] 或 [WARN] 行
   grep "\[ERROR\]\|\[WARN\]" debug.log

3. 記錄錯誤信息

4. 參考優化報告的故障排除部分

5. 如果問題持續，嘗試：
   - 重啟 Ollama
   - 重啟系統
   - 重新安裝模型
```
