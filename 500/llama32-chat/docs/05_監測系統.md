## 🔔 警報機制

### 自動警報條件

#### 1. 模型故障

- 連續 3 次失敗 → 標記為冷卻
- 成功率低於 90% → 發出警告
- 響應時間超過 5 秒 → 性能警報

#### 2. 系統資源

- 記憶體使用超過 80% → 資源警報
- 磁碟空間低於 10% → 存儲警報
- CPU 使用率持續 > 90% → 負載警報

#### 3. 任務狀態

- 任務失敗超過 3 次 → 任務錯誤
- 任務執行超過預期時間 2 倍 → 超時警報
- 待執行任務積壓超過 10 個 → 堆積警報

### 警報處理

系統會：

1. 記錄到日誌
2. 更新狀態文件
3. 在監控面板顯示
4. 觸發自動修復（如果可能）

## 🛠️ 自動修復

系統具備自動修復能力：

1. **模型故障**
   - 自動切換到備用模型
   - 冷卻期後自動重試
   - 記錄故障原因

2. **任務失敗**
   - 自動重試（最多 3 次）
   - 降低優先級
   - 通知管理員

3. **資源問題**
   - 清理臨時文件
   - 壓縮舊日誌
   - 釋放緩存

## 📝 日誌系統

### 日誌級別

- **DEBUG**: 詳細調試信息
- **INFO**: 一般信息
- **WARNING**: 警告信息
- **ERROR**: 錯誤信息
- **CRITICAL**: 嚴重錯誤

### 日誌文件

- `logs/agent.log` - 主要系統日誌
- `logs/import_log.json` - 導入操作日誌
- `logs/performance.json` - 性能數據日誌
- `logs/error.log` - 錯誤專用日誌

### 日誌輪轉

- 每日自動輪轉
- 保留最近 30 天
- 壓縮舊日誌
- 自動清理過期日誌
