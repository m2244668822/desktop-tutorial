## 🧠 中樞神經系統（Central Nervous System）

### 設計理念

模擬人類大腦的神經網絡結構，實現敏感、動態的決策能力。

### 神經網絡架構

```
輸入層 (Input Layer)
├─ 8 個神經元
├─ 信號: 查詢長度、詞彙豐富度、問題傾向、技術性等
└─ 輸出: 初步信號特徵
    ↓ (權重: 0.5±0.1)
語義層 (Semantic Layer)
├─ 6 個神經元
├─ 分析: 詞義、語言特性
└─ 輸出: 語義特徵向量
    ↓ (權重: 0.6)
上下文層 (Context Layer)
├─ 6 個神經元
├─ 分析: 歷史對話、相關性
└─ 輸出: 上下文評分
    ↓ (權重: 0.7)
情感層 (Emotion Layer)
├─ 5 個神經元
├─ 分析: 查詢情感傾向
└─ 輸出: 情感敏感度
    ↓ (權重: 0.8)
決策層 (Decision Layer)
├─ 5 個神經元
├─ 綜合: 模型選擇、置信度評估
└─ 輸出: 決策建議
    ↓ (權重: 0.9)
輸出層 (Output Layer)
├─ 5 個神經元
├─ 綜合: 最終決策和置信度
└─ 輸出: 模型選擇 + 敏感度指標
```

### 決策流程

```python
# 1. 輸入信號轉換
query = "如何優化 Python 代碼性能?"
signals = [
    0.17,  # 查詢長度 (歸一化)
    0.15,  # 詞彙豐富度
    1.00,  # 有問號
    0.53,  # 技術詞彙比例
    0.20,  # 複雜度
    0.50,  # 情感傾向 (中立)
    0.00,  # 專業性
    0.30   # 緊急性
]

# 2. 神經層激活
activations = {
    'input': 0.572,
    'semantic': 0.608,
    'context': 0.613,
    'emotion': 0.605,
    'decision': 0.621,
    'output': 0.627
}

# 3. 敏感度評估
sensitivity = {
    'keyword': 0.68,      # 關鍵詞識別
    'context': 0.613,     # 上下文理解
    'emotion': 0.605,     # 情感感知
    'confidence': 0.45,   # 相關性信心
    'overall': 0.627      # 整體敏感度
}

# 4. 模型決策
selected_model = "claude"  # 技術問題優選 Claude
confidence = 0.627         # 決策置信度
```

## 🔄 數據流設計

### 聊天數據流

```
用戶輸入
   ↓
chat.py (解析命令)
   ↓
autonomous_agent (中樞神經)
   ├─ 神經分析 (20-50ms)
   ├─ 模型選擇
   └─ 上下文檢索 (可選)
   ↓
選定的 AI 模型
   ├─ Ollama (本地)
   ├─ Gemini (API)
   ├─ Claude (API)
   ├─ OpenAI (API)
   └─ xAI (API)
   ↓
模型回應 (100-500ms)
   ↓
結果處理
   ├─ 記錄到 conversations.json
   ├─ 更新性能統計
   └─ 保存神經分析結果
   ↓
返回給用戶
```

### 任務執行流

```
任務創建
   ↓
tasks/tasks.json (持久化)
   ↓
task_manager.py (任務管理器)
   ├─ 讀取待執行任務
   ├─ 按優先級排序
   └─ 檢查依賴關係
   ↓
autonomous_agent (協調執行)
   ├─ 為每個任務選擇模型
   ├─ 分配執行順序
   └─ 監控執行進度
   ↓
執行任務
   ├─ 成功 → 記錄到 history.json
   ├─ 失敗 → 重試機制 (最多 3 次)
   └─ 超時 → 標記失敗
   ↓
更新任務狀態
   ↓
生成執行報告
```

### 故障轉移流

```
模型 A 調用
   ↓
失敗檢測
   ↓
記錄失敗
   ├─ 更新 agent_health.json
   ├─ 增加失敗計數
   └─ 記錄失敗原因
   ↓
autonomous_agent (決策)
   ├─ 檢查連續失敗次數
   ├─ 是否超過門檻? (3 次)
   │   ├─ 是 → 標記冷卻 (5 分鐘)
   │   └─ 否 → 繼續使用
   └─ 選擇備用模型
   ↓
模型 B 調用
   ├─ 成功 → 完成任務
   └─ 失敗 → 繼續轉移到模型 C
   ↓
最終結果
   ├─ 成功 → 返回結果
   └─ 全部失敗 → 返回錯誤
```

## 🔗 通信架構

### 消息代理（MessageBroker）

```python
class MessageBroker:
    """消息代理 - 實現發布/訂閱模式"""

    def publish(self, message: Message):
        """發布消息給所有訂閱者"""

    def subscribe(self, event_type: EventType, callback):
        """訂閱特定類型事件"""

    def unsubscribe(self, event_type: EventType, callback):
        """取消訂閱"""
```

### 事件系統（EventType）

```python
class EventType(Enum):
    """事件類型定義"""
    TASK_CREATED = "task_created"
    TASK_ASSIGNED = "task_assigned"
    TASK_COMPLETED = "task_completed"
    TASK_FAILED = "task_failed"
    MODEL_SELECTED = "model_selected"
    MODEL_FAILED = "model_failed"
    CODE_UPDATE_COMPLETED = "code_update_completed"
    CONVERSATION_SAVED = "conversation_saved"
```

### 智能體註冊（AgentRegistry）

```python
class AgentRegistry:
    """智能體註冊表 - 管理所有智能體"""

    def register(self, agent_id, description, capabilities):
        """註冊智能體"""

    def unregister(self, agent_id):
        """註銷智能體"""

    def get_agent(self, agent_id):
        """獲取智能體信息"""

    def get_all_agents(self):
        """獲取所有智能體列表"""
```

### 消息流示例

```
智能體 A (發送方)
   ↓
message_broker.publish(
    Message(
        sender="agent_a",
        event_type=EventType.TASK_COMPLETED,
        data={"task_id": "task_001", "result": "success"}
    )
)
   ↓
MessageBroker (中繼)
   ├─ 查找訂閱者
   └─ 分發消息
   ↓
智能體 B (訂閱者 1)
智能體 C (訂閱者 2)
中樞神經 (訂閱者 3)
   ↓
各自處理消息
```

   ├─ 依賴: neural_hub.py

## 🔒 安全設計

### API Key 管理

- 存儲在 `.env` 文件
- 不提交到版本控制
- 運行時加載
- 加密傳輸

### 數據隱私

- 本地存儲對話數據
- 不上傳到外部服務器
- 用戶完全控制數據

### 錯誤處理

- 優雅降級
- 異常捕獲
- 詳細日誌記錄
- 用戶友好的錯誤提示

## 📈 可擴展性

### 添加新模型

1. 在 `constants.py` 添加模型配置
2. 在 `autonomous_agent.py` 實現調用邏輯
3. 在 `.env` 添加 API Key
4. 更新健康檢查

### 添加新智能體

1. 繼承 `BaseAgent` 類
2. 實現 `handle_message` 方法
3. 註冊到 `AgentRegistry`
4. 訂閱相關事件

### 添加新功能

1. 創建新模塊文件
2. 集成到現有架構
3. 更新文檔
4. 添加測試
